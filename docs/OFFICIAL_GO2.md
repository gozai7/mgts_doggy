## Запуск

Требуется собранный `mgts-competition-glim:gpu`. На тестовом ноутбуке выполните `export DOCKER_CONTEXT=mgts`.

```bash
make go2-rviz PHASE=localization      # исходные измерения B в RViz, по кругу
make go2-map                         # GLIM на A
make go2-locate                      # исходный холодный поиск и NDT на карте GLIM
make go2-live RUN_NAME=demo-01        # карта из штатных облаков A, поиск старта и коррекция позы по поверхностям на B при 1×
make go2-result RUN_NAME=demo-01      # RViz с записанным результатом demo-01
```

Для нового живого прогона выберите свободное имя. Без RUN_NAME оно формируется по времени. В исходном эксперименте с GLIM v2 поиск старта для NDT завершился ошибкой связывания последовательных сканов. Для итогового прогона используйте `go2-live`. На уже созданном неуспешном checkpoint раннер сохраняет диагностику и отказывается перезаписывать каталог.

## Что входит в замер

В GLIM подаются записанные `cloud_base` и `utlidar/imu`. Поворот IMU оценён по сопоставлению гироскопа и направления тяжести с одометрией A. Для плеча IMU принято положение центра лидара. Медианная норма ускорения составляет 9,71 м/с² на A и 9,80 м/с² на B. Во всех сообщениях IMU три матрицы ковариации заполнены нулями. По 2 477 соседним отсчётам в 20 спокойных полусекундных окнах A оценены эффективные плотности белого шума. Для каждой оси взята робастная оценка стандартного отклонения разностей через MAD, умноженная на √(Δt/2). Медианы по трём осям составили 0,00737 (м/с²)/√Гц и 0,000329 (рад/с)/√Гц. Для случайного дрейфа смещения оставлены параметры GLIM. Это оценка на коротких участках работающего робота.

По сырым сообщениям A/B максимальное `time` точки коррелирует с интервалом до **следующего** скана (0,924 / 0,938). Оно записано как float32 в секундах относительно начала скана. Перед прибавлением к метке Unix смещение переводится в float64. Та же конвенция времени описана в [SDK Unitree](https://github.com/unitreerobotics/unilidar_sdk2/blob/main/unitree_lidar_sdk/include/unitree_lidar_utilities.h#L50-L67).

В `go2-live` карта строится накоплением штатного `cloud_deskewed` из A. Глобальный поиск на B сопоставляет короткую последовательность сканов с картой, используя только относительное движение из одометрии B. После разрешения конкурирующих гипотез каждый скан `cloud_base` получает позу. Лучи приводятся ко времени начала скана по уже полученной одометрии корпуса. Лидарная поправка использует расстояния до локальных плоскостей карты вдоль наблюдаемых направлений, остальные компоненты задаёт одометрия. Чётные и нечётные точки разделены между расчётом поправки и её проверкой. При отклонении поправки публикуется прогноз с последним принятым преобразованием между одометрией и картой.

В `results/<имя>/` сохраняются `timing.json`, `initialization.json`, `map.pcd`, `trajectory.tum`, `tracking.csv` и `result_bag/`. Для каждой позы источник `lidar` или `odometry` записан в топик `/competition/result/source`. До обнаружения старта абсолютные позы отсутствуют. Задержка измеряется от записанного момента поступления облака до получения ROS-сообщения с позой. Стенд — Ryzen 5 5600H, RTX 3060 Laptop. Экспериментальная ветка GLIM использует GPU, итоговый трекер работает на CPU.
