# МГТС · GLIM на GPU

Комплект для 64-разрядного Linux x86-64 с Docker Engine и NVIDIA GPU, доступной контейнерам через CDI или NVIDIA Container Toolkit. Образ содержит ROS 2 Jazzy, CUDA 12.6, GLIM, NDT и обработчик бэгов. Команды выполняются из распакованной папки. Загрузка образа при первом запуске выполняется с диска.

1. Запустите `./run.sh gpu-check`. При успехе команда покажет число доступных CUDA-устройств.
2. `./run.sh smoke-test` проверяет построение карты, поиск неизвестного старта и локализацию на синтетической паре записей.
3. Положите каталоги бэгов в `data/mapping/` и `data/localization/`. Для отдельного MCAP укажите путь внутри `/data` в `dataset.yaml`.
4. Запустите `./run.sh doctor` и `./run.sh doctor --phase localization`. Заполните в `dataset.yaml` топики, единицы, измеренные трансформации LiDAR/IMU и формат времени точек. Для неизвестного старта оставьте `initial_pose: null` и `manual_initial_pose: false`.
5. Запустите `./run.sh`. Результаты появятся в `results/run01/`. Карта находится в `occupancy/map.pgm` и `occupancy/map.yaml`, маршрут B — в `localization/trajectory.csv`. Файл `localization/initialization.json` содержит автоматически найденную позу и оценки гипотез. Для другой пары бэгов укажите новый каталог `output`.

Топики и калибровки шаблона нужно сверить с данными организаторов. Глобальный поиск рассчитан на одноэтажную карту. При неоднозначной геометрии обработка может завершиться ошибкой поиска начальной позы.

Для официальных записей Go2 положите бэги в `data/mapping/` и `data/localization/`, затем выполните `./run.sh go2-live demo-01`. В этом режиме используется встроенный профиль Go2. Трёхмерная карта, маршруты, результаты замера 1× и ROS 2 bag сохраняются в `results/demo-01/`. Для повторного замера выберите новое имя.
