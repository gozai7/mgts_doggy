# Отчёт проверок — 26 ноября 2026

## Fast-LIO на ROS 2 Jazzy

Проверены сборка Fast-LIO и ROS-интерфейсов Livox из закреплённого исходника,
сборка `lidar_localization_ros2` с `ndt_omp_ros2` и сборка KISS-ICP. Среда Ubuntu 24.04,
Jazzy, PCL 1.14, Eigen 3.4 и версии Python из `requirements-competition.txt`.
Проверка компоновки установленных узлов не выявила отсутствующих библиотек.
`rosdep install -s` разрешил зависимости всех пяти пакетов для Jazzy.
`make test-unit` прошёл 53 теста. Отдельный запуск KISS-ICP выдал 201 позу на 201 облако A.

Сквозной сценарий запущен через `tools/ros_smoke.sh` с локально собранными ROS-пакетами.
Штатный CPU-образ `mgts-competition-fast-lio:cpu` успешно собран через `make build`.
В этом образе `make smoke-test` прошёл обе версии сценария с `network_mode: none`.
Повторный запуск Python-тестов в образе дал 53 из 53. Проверка подготовленного образа
подтвердила те же метрики и файлы результата, что и локальный прогон.

1. Генератор создал две пары записей A/B для одной асимметричной комнаты. В каждой A было
   201 облако за 20 секунд при 10 Гц и IMU при 100 Гц. B начинается на девятой секунде,
   когда робот уже движется, и содержит 111 облаков. Шум точек в B сгенерирован отдельно.
   Для второго прогона лучи собраны за 90 мс с учётом движения в момент каждого измерения.
2. Bag Doctor проверил данные. Пайплайн нормализовал их и передал запись A в Fast-LIO.
   Узел экспортировал PCD, IMU-траекторию и облака, синхронизированные с позами на конец
   скана. В обоих прогонах два скана ушли на инициализацию. В режиме deskew последний
   скан вышел за границу записи IMU и был пропущен.
3. При `initial_pose: null` BBS и ICP нашли стартовую позу B по карте A. Для подтверждения
   позы использовался отдельный скан. `lidar_localization_ros2` затем обработал запись B
   с начала методом NDT_OMP. Для каждого скана replay дождался статуса регистрации.
4. Пайплайн построил 2D-карту из сохранённых облаков, записал TUM/CSV, PGM/YAML,
   OccupancyGrid и диагностику. Повторный запуск с теми же параметрами использовал
   сохранённые этапы A, B и 2D-экспорта.
5. Эталон генератора использовался после завершения SLAM. Позы сопоставлялись по времени
   в общей системе, заданной неподвижным началом A.

| Сценарий | Позы A | Покрытие A по времени | Точек в PCD | Позы B | RMSE A, 3D | RMSE B, XY | RMSE B, Z |
|---|---:|---:|---:|---:|---:|---:|---:|
| Без времени точек | 199 | 99,0% | 1441 | 111/111 | 1,47 см | 2,77 см | 23,65 см |
| Время точек и deskew | 198 | 98,5% | 1489 | 111/111 | 1,42 см | 4,89 см | 25,10 см |

Автостарт B занял 1,2 с входной записи в обоих режимах. В 2D-экспорт вошли
100 и 99 облаков соответственно. Для всех использованных облаков найдены позы.
Дополнительный прогон проверил смещения и повороты обоих датчиков и отрицательные
смещения времени точек от stamp конца скана. Получено 198 поз A и 111 из 111 поз B.
Отдельный прогон GICP на тех же входах дал 3D RMSE B 0,45 см без времени точек и
25,94 см с ним. Результат показывает чувствительность вертикальной оценки к геометрии
в этой сцене. Проверка проводилась на синтетических записях. Точность на реальном роботе
и данных соревнования остаётся непроверенной.

При интеграции выяснилось, что экспортируемый rosbag требует хеш типа сообщения
для чтения через `rosbags`, а `ros2 run` мог оставить узел локализации после завершения replay.
После исправлений оба сценария были повторены подряд.

## Проверка командного образа GLIM на RTX 3060 Laptop

Linux x86-64, драйвер 615.78.08, CUDA 12.6 внутри контейнера. Проверены CUDA-вычисление, сборка GLIM и его ROS-обёртки из закреплённых исходников, сборка KISS-ICP и NDT. Python-тесты прошли, 52 из 52. Готовый образ выгружен и загружен в отдельный пустой Docker Engine на том же ноутбуке. Запуск из распакованного комплекта без сети повторил обработку A и B и экспорт 2D-карты.

Синтетический B начинается в движении. Во входном конфиге начальная поза отсутствует. Одноэтажная комната, четыре горизонтальных ряда точек на стенах. Метрики ниже посчитаны по 111 временным меткам относительно независимой траектории симулятора в системе карты, без подгонки траекторий. Каждая строка использует одну и ту же карту и одинаковую начальную позу.

| Регистрация B | Принято | RMSE XY | RMSE Z |
|---|---:|---:|---:|
| NDT_OMP, ячейка 0,5 м (базовая) | 111/111 | 4,67 см | 14,87 см |
| NDT_OMP, ячейка 0,8 м | 111/111 | 1,78 см | 1,50 см |
| GICP | 111/111 | 0,06 см | 0,59 см |

В исходном PCD 993 точки. При 0,5 м порог NDT в шесть точек выполняют 18 из 346 занятых ячеек, при 0,8 м — 83 из 123. В контроле с более плотным PCD (2573 точки, повторная сборка облаков A по оптимизированным позам) и ячейкой 0,5 м RMSE Z выросла до 28,3 см. На этой геометрии чувствительны распределение точек по ячейкам и сам метод регистрации.

При ячейках 0,25 м и 0,35 м NDT принял только 20 и 9 сканов соответственно, оба запуска не прошли порог покрытия. Автостарт базового прогона потребовал 6 секунд наблюдений, ошибка первой найденной позы составила 1,35 см и 0,54°. Отдельный тест на двух одинаковых копиях комнаты проверяет отказ при неразрешимой неоднозначности.

На 49-секундной записи Gazebo `office-B` проверен отдельно маппинг с 473 облаками и IMU. Получены 462 позы. После совмещения по первой общей позе в SE(2) RMSE по XY составила 2,75 мм на 6,14 м эталонного пути. Соревновательные бэги и ноутбуки организаторов в этих проверках не использовались.

Тесты покрывают SQLite3/MCAP, PointCloud2 endian/row padding/поля времени,
SI-конверсию и ковариации, защиту оригиналов, ошибки timestamp/extrinsics,
Slerp без экстраполяции через gaps, lever arm, raycasting/unknown endpoints,
seeded fault injection, знак временного сдвига, low-excitation отказ,
APE/RPE на аналитических траекториях, PCD reader и повторное использование нормализованных
данных после изменения initial pose/пола. Сверены имена используемых localizer parameters.

**Fixture poses использованы только для проверки экспортера OccupancyGrid.
Это не результат SLAM.** Ни один алгоритм не получил эталонную траекторию как собственный результат.
Синтетическая сцена не является benchmark реального робота; точность, производительность
GLIM/RKO и качество локализации по этим проверкам не установлены.

- `docker build`, C++ compile/link и upstream C++ test suites.
- Полный `make smoke-test` с ROS, GLIM/RKO/graph/localizer/KISS.
- Реальный bag, APE/RPE реального SLAM, loop acceptance и устойчивость в офисе.
- CUDA/VRAM/CPU/RAM profiling, RViz, PlotJuggler и GLIM offline viewer.
- Повторный запуск исходного legacy 2D pipeline.

В среде подготовки не было docker, ros2, colcon, cmake и доступной ROS runtime.
Проверка исходников/API не заменяет компиляцию. Патч rosbag2 Writer сверялся с Jazzy:
в write передаётся объект сообщения, не shared_ptr.
