# Карта, видимость и входные сенсоры

## Что требуют и что можно продемонстрировать сегодня?

### Takeaway

Наиболее защищаемая функция — показать, где проход A и инспекция B дали **противоречащие измерения одной области**, а где робот просто не посмотрел. Такой слой можно проверить отдельно от AMCL. Его польза для диагностики и потенциальное улучшение итоговой сетки — разные гипотезы.

- Подготовить до финала читаемый отчёт входных полей, временного покрытия и геометрии. По каждой записи сохранять размер, список/типы полей, систему координат, единицы, длительность, конечные точки, заполненность секторов до/после среза, причины отказа. ## Как получить устойчивую карту A и диагностировать изменения при инспекции B?

### Takeaway

Практичный первый шаг — второй офлайн-проход по окончательным позам с независимыми свидетельствами «луч закончился» и «луч прошёл». Второй результат — опциональная очищенная карта A, только после проверки сохранности статических стен и препятствий. B остаётся измерением изменений на фиксированной карте A.

### Cited Findings

- Hornung и соавт. описывают физическую модель обновления: ячейки до измеренного конца свободны, конечная занята, неувиденная область остается неопределённой. Для борьбы с ложными отверстиями при скользящих углах наблюдения авторы дают концу луча приоритет над проходом в рамках одного обновления облака. Качество они также проверяли по отложенным сканам. Оригинал — объёмная карта, 2D слой ниже является адаптацией. [Hornung et al., Autonomous Robots, 2013](https://www.ipb.uni-bonn.de/wp-content/papercite-data/pdf/hornung13auro.pdf)
- ERASOR оценивает как удаление динамических следов, так и сохранение статики, в том числе описывает ошибки при окклюзии, косом падении луча и частичном обзоре. Прямое применение в офисе не подтверждено: исходная реализация проверялась на автомобильном SemanticKITTI и использует вертикальную структуру, связанную с наземными объектами. [Lim et al., ERASOR, 2021](https://arxiv.org/abs/2103.04316)
- В репозитории оценка IoU строится по ячейкам внутри границ с известным прогнозом. Если после агрессивной фильтрации перевести сложные участки в unknown, IoU способна возрасти за счёт выбора меньшей области. Показатель observed_fraction уже существует. Визуализация B хранит лишь часть концов без истории проходов. [Чекер](/home/legion/MGTS/solver/evaluate.py:166) · [Запись B](/home/legion/MGTS/solver/solve.py:189)

### Inferences

- Вход слоя A — сканы, реальные начала лучей и окончательные ключевые позы из графа. Для первой версии взять только метки ключевых сканов, не линейно интерполировать конечные позы через разрыв 38,8 с или неконтролируемый поворот. Если нужны остальные сканы, перенести соседнюю поправку map←odom локальной одометрией с контролем разрыва и проверить отдельно. Для B читать полные сканы и позы; после глобального старта исключить неоднозначную локализацию по независимому критерию качества, отдавать «поза не подтверждена».
- 2D реализация средней сложности: на базовой сетке A копить число разнесённых окон/ключевых поз, где ячейка была конечной или действительно пересекалась лучом. Если десятки лучей прошли из одной позы — один голос в этом окне. В идеале потребовать второй ракурс либо разнесённый во времени возврат. Конец сильнее прохода из того же скана, проход заканчивается с запасом до отражения по разрешению и неопределённости; за первой поверхностью свидетельств нет. Пустой угловой бин разреженного облака и недокументированный inf/NaN не прочищают пространство. Для известного сенсора пригодны документированные измерения «нет препятствия до такой-то дальности», отдельно от пропущенных измерений. Не выдавать коэффициент голосов за откалиброванную вероятность.
- Для A сравнить базовую сетку и маску кандидатов: подтверждённые из разных поз препятствия сохранить, однократный возврат с повторными независимыми проходами через ту же область пометить как вероятный временный след. Простое правило «мало hits → стереть» уберёт стойки, мебель и границы стекла. Геометрическое противоречие в пределах погрешности положения также не означает движение; у границ использовать буфер по неопределённости позы, ширине бина и сетке. Слабое наблюдение остаётся неизвестным/неуверенным. Если очищенный вариант не выигрывает по тестам, отправить штатную карту и показать диагностический слой.
- Для B отдельно вывести «появилось» (A подтверждённо свободна, B многократно дал конечные точки), «освободилось» (A регулярно давала конечные точки, B пронёс лучи сквозь старое место к дальнему возврату), «впервые увидено», «недостаточно обзора», «локализация ненадёжна». Сначала проверять качество позы на независимой статической части, затем объединять пространственно соседние ячейки; подпись содержит площадь и число независимых наблюдений. Сравнить с отрицательным A→A, с небольшим преднамеренным сдвигом позы B и с закрытием бывшего препятствия ближним объектом. Не обновлять A при подсчёте метрик B, не использовать изменения B для обратного «улучшения» тестовой карты.
- Вертикальная неоднозначность: в 2D лазер, прошедший **над** стулом, не опровергает его нижнее попадание. Если доступны xyz, достаточно 2–3 физических полос по высоте и расчёта пересечения каждого 3D луча с соответствующей полосой; свободность давать только участку луча внутри полосы. Первая версия может оставить для доказательств прохода почти горизонтальные лучи из выбранной полосы. Произвольная проекция начала и конца с разных высот создаёт ложные свободные коридоры. Согласие нескольких полос повышает доверие к стенам, одиночная полоса полезна для низких и тонких предметов. Для чистого LaserScan вариант только плоский, с контролем наклона.
- Оценка затрат: на растр 322×360 две карты голосов uint16 плюс одно uint32 последнее окно дают порядка 0,89 МиБ на один слой без временных масок; три вертикальных слоя — около 2,7 МиБ. Стоимость точного прохода по лучам O(∑ число пересечённых ячеек), грубая верхняя оценка порядка Nсканов × Nлучей × дальность/шаг. Для 812×360×320 получается около 94 млн проходов на максимальной дальности, не замер времени; ключевые кадры и нативный обход снижают затраты. Полная плотная 3D сетка при высоте 2 м и шаге 5 см дала бы 40 таких слоёв плюс накладные расходы. Полную 3D реконструкцию для сдачи 2D карты отложить.
- Тест с GT до финала. (1) Одно и то же окружение статично: фиксированные позы, отложенные сканы, тонкая стойка, низкое препятствие. (2) Идущий через луч человек/ящик во время A, с укорочением первой дальности и удалением возвратов за ним; статический фон за объектом должен стать видим при следующем ракурсе. (3) Изменение A→B: коробка на старом видимом месте и новом месте с подтверждённой свободностью в A, общая видимость, плюс частично скрытый объект. (4) Отрицательные варианты: те же данные/окружение без изменений, отсутствующий сектор, наложение с ошибкой yaw, разные высоты обзора. Взять одинаковые позы для сравнения растеризации, затем повторить вместе с полной локализацией. По симулятору вынести отдельно истину о поверхности/освещённых лучами ячейках и недоступной внутренности коробки.
- Метрики: исходный known-only IoU и observed_fraction парой; IoU/TP,FP,FN на **общей до опыта фиксированной области**, покрытие и доля воздержаний; явный учёт unknown на видимых GT-поверхностях как пропуска в recall. При расхождении FOV сравнивать фиксированную маску видимости от рендеринга GT и отдельно приводить долю общего обзора. Для стен/стойки — полнота возвратной поверхности и разрывы проекции, в дополнение строгий и с допуском в одну ячейку варианты. Для динамики — сколько временных ячеек удалено и столько ли статических сохранено, precision/recall событий в наблюдаемой части, ложные события на статике. Записать те же RMSE/покрытие B как защиту от ухудшения пригодности карты. Выигрыш объявлять только при росте подавления следа без потери наблюдаемой площади, тонких объектов и качества B в предписанных пределах, зафиксированных до сравнения.
- Без GT на финале — независимые окна отложенных сканов: ошибка между измеренной дальностью и первым ожидаемым препятствием, доля концов вблизи занятости, доля проходов через ранее занятое, доля известного обзора; по стабильным стенам и дефицитным секторам отдельно. При исключении данных из построения карты исключить их также из получения поправки позы либо явно назвать проверку условной на оценённой позе. Это показатели согласованности, совместный дрейф и неверную симметричную локализацию они не выявляют; абсолютную точность не выводить. Схематичный план — независимая визуальная/топологическая проверка, если нет масштаба и привязки.

### Gaps

- Из saved preview B нельзя восстановить полное покрытие лучами. Пиксельная формулировка «135 неизвестных внутри коробки» не даёт ошибки SLAM: отражение даёт поверхность, а не видимость внутренности. Статус перемещения в реальном bag заранее неизвестен.

## Какие улучшения подготовки сенсоров оправданы?

### Takeaway

Сначала проверять геометрию и информативность существующей проекции. Тайминг отдельных точек нужен для полноценной компенсации движения; у обеих проверенных локальных записей его нет. Камера пригодна только в объёме подтверждённой схемы.

### Cited Findings

- Поля PointCloud2 перечисляет само сообщение; стандарт допускает организованные и неорганизованные облака, не задаёт обязательный канал времени. Для LaserScan header соответствует первому лучу, time_increment — промежуток в секундах между измерениями, scan_time — промежуток между сканами. [PointCloud2.msg](https://raw.githubusercontent.com/ros2/common_interfaces/jazzy/sensor_msgs/msg/PointCloud2.msg) · [LaserScan.msg](https://raw.githubusercontent.com/ros2/common_interfaces/jazzy/sensor_msgs/msg/LaserScan.msg)
- В LIO-SAM исходная компенсация использует известное относительное время точки, сканерные каналы конкретной реализации и преобразования IMU. Это обоснование требования времени, а не доказательство пригодности всего пакета для неизвестного офисного лидара. [Описание авторов LIO-SAM](https://github.com/TixiaoShan/LIO-SAM#prepare-lidar-data)
- Текущая проекция использует одну позу на scan stamp; валидное исходное время отдельных лучей/точек при такой обработке теряется, угловые бины создаются заново. На примерах эталон A имеет только плоский скан, B облако без времени точек; оба годятся для проверки режима отказа от поточечной коррекции. ### Inferences

- Устойчивый срез, средняя сложность. Логировать roll/pitch и количество занятых угловых бинов, долю точек у пола, провалы по секторам, изменение проекции монтажного смещения. На XYZ при повторяемой потере опор сначала сравнить фиксированную полосу после имеющегося выравнивания и две фиксированные полосы относительно надёжного пола. Если пол виден, брать устойчивую плоскость с нормалью около гравитации, достаточным пространственным охватом и проверенной высотой. При низком доверии сохранять проверенный срез. На чистом LaserScan произвольное расширение высотной полосы не добавит данных, а при наклоне плоскость может смотреть в пол, поэтому измерять влияние крена/тангажа и отбрасывать только доказанно плохие сектора. Слепое расширение полосы добавит потолок, столешницы, собственный корпус. Вторую полосу можно изначально делать диагностической, сохраняя независимую от неё базовую A.
- Показательный тест качки: синтезировать 3D возвраты от одной геометрии при известных крене/тангаже, смещении сенсора и нескольких высотах объектов. Сравнить исходный фиксированный обработчик (уже устраняет часть наклона) и новый вариант; логировать отклонение конечной точки для вертикальной стены, потери на стойке, ложные «стены» от пола, угловой охват и качество принятых поз. Отдельно сделать тест с ошибочным TF или акселерометром при разгоне. Не подгонять плоскость пола под каждую группу точек без проверки.
- Условный deskew, средняя/повышенная сложность. Для LaserScan — time_increment достоверен и >0, источник действительно выдаёт последовательный скан. Для PointCloud2 — документированы время абсолютное/относительное, единицы, момент header, согласованный такт, продолжительность. Проверить разброс внутри кадра, конечность, границы, характер соседних кадров и покрытие IMU/локальной позой всего интервала; нулевые времена и scan_time сами по себе непригодны. С неорганизованным облаком порядок массива и ring не кодируют абсолютную фазу. В допустимом случае T_pose(t_ref)^(-1) T_pose(t_i) приводят точки к одному времени в общей системе с экструзикой, и лишь затем выполняют отсев высот и биннинг. Использовать исходный луч и его начало для расчёта свободности. Не добавлять повторно гироскоп в уже слитый EKF. При дыре в IMU/позе субинтервал помечается, штатный скан проходит без deskew. Отдельный тест с синтетической построчной развёрткой, известным поворотом и контрольным случаем мгновенного скана; сравнить ширину стены и остатки на поворотах. Заранее проверять ожидаемый линейный смаз по порядку (скорость + дальность × угловая скорость) × длительность скана относительно 5 см. На медленной записи выигрыш может быть меньше разрешения карты.
- Камера, низкая сложность для диагностики, высокая для слияния. Если только 2D координаты на кадр — временное покрытие, количество и распределение по полю зрения; переменный размер потока не доказывает движение робота. Если подтверждены устойчивые ID между кадрами или описанные совместимые дескрипторы, intrinsics/distortion, TF и синхронизация — геометрически проверенная оценка относительного поворота либо независимый сигнал деградации на отложенном участке; исключить близкие вырожденные кадры, движущихся людей, проверить ошибки по статическим соответствиям. Монокулярное смещение в метрах не наблюдается без масштаба. Межпроходные совпадения ID без гарантии пространства идентификаторов не использовать. Без RGB обычный оптический поток, ORB-extraction и визуальный place recognition по картинкам не входят в практический план.
- На защиту: первым выбором сделать наблюдаемость и аудит карты на двух записях (средняя инженерная сложность; зависит от сканов, TF, надёжных поз). Условная очистка A и многослойная проекция обосновываются конкретными ошибками и отдельными абляциями. Полный LIO/VIO, 3D сегментацию людей и попытки универсально «починить стекло» по одному редкому возврату отложить.

### Gaps

- У обработчика нет данных для положительного испытания поточечной компенсации на сохранённых местных SCAN/XYZ. Межкадровые ID, время, дисторсия, устойчивый горизонт, видимость пола, 6D одометрия и качество калибровки на финальных записях пока являются условиями выбора веток, а не исходными фактами.
